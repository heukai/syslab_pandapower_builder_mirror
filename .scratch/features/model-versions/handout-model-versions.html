Which model for which day?

The SYSLAB grid changes over the years, and the pandapower model has to follow. We want to publish several model versions side by side and let every analysis pick the right one for the date of its data. This page explains the idea and asks for your view on how publishing and choosing should work.

Four words we use

Configuration era
E6, E7

A period marked by a major change of the grid: usually a new switchboard. Named after the overview figure (figure v7 → era 7).

Operational period
6-a … 6-d

Inside an era, the switchboards actually in operation. The 2023 rebuild was commissioned in four stages, and experiments ran in between.

Configuration revision
6.3, 6.4, 6.5

A set of smaller changes inside an era: a renamed bay, a second meter. Recorded as change entries with their evidence.

Model version
6.4.2 · 6.4.2/j1a-2026

A published model of one revision, improved over time and validated on real days. A scenario model adds an experiment's set-up.

How a date finds its model

An analysis asks for the model of a day. The answer is picked in this order, and the answer always says how good it is.

1Era. The date falls in one configuration era (and one operational period inside it).
2Validated on that day? A model of the era that was checked against measured data on that day wins.
3Valid for that period? Otherwise a model whose validity period covers the date.
4Base model of the era. Otherwise the latest general model of the era: it applies, with fewer guarantees. Scenario models are never the default.
5Behind? If the grid changed after the model was built (a confirmed change it does not include), the answer carries a warning.

What gets published, and what stays inside the lab

The model package syslab_pandapower is public. The configuration history behind it comes from the lab's own repositories, which are not.

What we would like your view on

  1. Choosing a model. Should an analysis pick the model by date automatically, or should the user always name a version? Our draft: by date, and the answer says which version and how good it is.
  2. When is a model "validated" for a day? Which check, and how close is close enough? Our draft: every island of the day simulated against its grid meter; the largest island within about 0.5 kW RMSE at 1-minute resolution.
  3. Data that spans an era change. Split the analysis at the change, or warn and use one model? Our draft: split, and say so.
  4. How many versions stay available? All versions side by side, or the latest per revision plus an archive?
  5. Who records a validation? After a yearly experiment, who checks the model against that day and writes it down?
  6. Which past days are worth checking? Experiments in 2023 to 2025 that would let us validate older revisions (6.0 to 6.3).

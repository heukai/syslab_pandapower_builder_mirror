Which model for which day?

The SYSLAB grid changes over the years, and the pandapower model has to follow. We want to publish several model versions side by side and let every analysis pick the right one for the date of its data. This page explains the idea and what the staff said about publishing and choosing.

Four words we use

Configuration era
E6, E7

A period marked by a major change of the grid: usually a new switchboard. Named after the overview figure (figure v7 → era 7).

Operational period
6-a … 6-d

Inside an era, the switchboards actually in operation. The 2023 rebuild was commissioned in four stages, and experiments ran in between.

Configuration revision
6.5, 6.6, 6.7

A set of smaller changes inside an era that came into force together: a renamed bay, a second meter. Numbered in time order and recorded as change entries with their evidence.

Model version
6.6.2 · 6.6.2.J1A

A model of one revision, improved over time and validated on real days (the third number). A variant adds an experiment's set-up, named by a project code (the fourth part).

How a date finds its model

An analysis asks for the model of a day. The first two numbers follow the lab's changes, so the date picks them; the answer always says how good the model is. (Agreed with the staff, 2026-10-30.)

1Era and revision. The date falls in one configuration era and one configuration revision: the first two numbers, 6.7.
2Best model of that revision. Its highest third number: the most validated, most accurate model, 6.7.1. Older ones of the same revision stay in the history.
3Validated on that day? The answer says whether the model was checked against measured data on that day, or only on other days, or not yet.
4No model of that revision yet? Then the nearest model of the era applies, with fewer guarantees, and the answer names the changes it lacks. Variants (an experiment's set-up) are never the default.
5Data across an era change? Rare; the analysis keeps one model and warns.

What gets published, and what stays inside the lab

The model package syslab_pandapower is public. The configuration history behind it comes from the lab's own repositories, which are not.

What the staff said (2026-10-30)

  1. Choosing a model. By date: the date picks era and revision, then the best model of that revision. As drafted.
  2. When is a model "validated" for a day? Not discussed; every island of the day simulated against its grid meter, the largest within about 0.5 kW RMSE at 1-minute resolution, seems fine.
  3. Data that spans an era change. Warn and use one model; it is unlikely to happen. Our draft (split) did not hold.
  4. How many versions stay available? All of them: models are small. Superseded models of a revision fade into the version history.
  5. Who records a validation? The toolbox that builds the models also holds the validation.
  6. Which past days are worth checking? The experiments repeated every year with slightly changed set-ups, in June and in November or March.
  7. New: a fourth part of the number for variants that add cables or equipment for one experiment, named by a project code (6.6.2.J1A). Its exact form is still open.

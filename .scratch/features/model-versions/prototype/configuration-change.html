Ticket "Hypotheses for what one configuration change is" (builder, map "dated model versions"). Real data: the v6 → v7 era change of 2026-10-05 and the Boiler rename of 2026-08-13, as seen in syslab/conf (hardware.xml), the Java displet, the overview figure, the FTP headers and our curated data.

The question. The lab sources report changes separately and on different days. Which record should hold a configuration change, so that (a) configuration eras and dated model versions follow from it, (b) every claim keeps its source and date, (c) disagreements, lag and planned equipment stay visible, and (d) the technical staff can read and correct it? Below, the same observations are written down under three hypotheses side by side. Press the observation buttons (free play) or follow a scenario tab, and compare the records, the eras and the generated change log.

Rules applied (maintainer): hardware.xml is authoritative for switchboards, bays and breakers; curated or declared data for cables; Java and figure are evidence; figure-only equipment is planned; logging lag and label mix-ups are flagged, never corrected.
